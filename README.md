# আছস? (Asos?)

A cross-platform, privacy-first, **offline** interactive learning agent inspired by Clippy.
Asos sits in the corner of your screen, guides you step-by-step through computer tasks
(like writing and running your first Java program), watches your file system to detect
your progress in real time, and answers questions with a **locally running AI model** —
no internet connection, no data ever leaving your machine.

The name comes from everyday Bangla chat: **"আছস?"** ("Hey, are you there?") — the friendly
nudge you send a close friend when you need a quick hand.

## Features

- **Interactive corner agent** — a persistent, always-on-top JavaFX companion with
  instructions, notifications, and a chat window
- **Chunked learning modules** — Java, Python, and C++ courses delivered in small,
  digestible steps that wait for you to actually complete each action
- **Real-time progress detection** — recursively watches your Desktop, Documents, and
  working directories; detects file creation, code content, and successful compilation
  (`.class` artifact detection) and verifies your program's output automatically
- **Adaptive pacing** — merges steps for fast learners, offers hints when you're stuck
- **Offline AI tutor** — chat answers generated by a small local LLM served by
  [Ollama](https://ollama.com) (default model: `qwen2.5:1.5b-instruct`, ~1 GB, runs on
  CPU-only machines). Falls back to rule-based responses if Ollama isn't installed,
  so the app always works
- **Progress persistence** — your course progress and profile are saved locally as JSON
  under `~/.asos/`

## Requirements

- Java 17 (LTS)
- Gradle
- [Ollama](https://ollama.com) — optional, but required for real AI chat answers

## Setup

### 1. One-time AI setup (optional but recommended)

```
winget install Ollama.Ollama        # or download from https://ollama.com
ollama pull qwen2.5:1.5b-instruct   # ~1 GB, one-time download
```

After this one-time download, everything runs fully offline. If Ollama isn't running
when Asos starts, the app tries to launch `ollama serve` itself; if Ollama isn't
installed at all, chat gracefully degrades to rule-based answers.

To use a different model or server, pass JVM flags:

```
-Dasos.ollama.model=llama3.2:1b
-Dasos.ollama.url=http://localhost:11434
```

### 2. Build and run

```
gradle build
gradle run
```

### 3. Run the tests

```
gradle test
```

## Architecture

| Component | Role |
|---|---|
| `AsosApplication` | JavaFX corner UI, notifications, menus, chat window |
| `ChunkTeachingEngine` | Finite-state teaching loop: instruction → monitor → feedback → next chunk |
| `RealTimeMonitor` | Detects learner actions: file events, code content, compile artifacts, verified program runs |
| `FileSystemWatcher` / `FileSystemMonitor` | Recursive `WatchService`-based monitoring with full-path reporting |
| `LocalAIEngine` | HTTP client for the local Ollama server (`/api/chat`), with rule-based fallback |
| `ModelManager` | Checks/pulls the local model through Ollama's API |
| `IntelligentLearningAssistant` | Builds persona/learning-style-aware prompts, post-processes answers |
| Learning modules | JSON chunk definitions in `src/main/resources/learning-modules/` |

### Why Ollama instead of raw ONNX?

An earlier iteration targeted Gemma 270M through ONNX Runtime directly, which required
hand-building tokenization and the generation loop — impractical to make reliable, and
the 270M model was too weak for tutoring. The project now delegates model serving to an
Ollama sidecar over its local HTTP API and uses a stronger small instruct model
(Qwen2.5 1.5B), keeping the app 100% offline while removing an entire class of
low-level inference code.

## Known limitations

- Compile/run auto-detection is currently implemented for the **Java** pathway;
  Python/C++ module steps that expect terminal output still need manual progression
- The app verifies your program by running the compiled class itself in the background —
  it cannot see commands typed into your own terminal window
